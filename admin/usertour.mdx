## Why UserTour

PostGlider is self-serve: users arrive at `/dashboard` after onboarding with a complete business profile but no muscle memory for the product. They have one generated idea (from the `/free-trial` flow) and an empty vault. The gap between "account created" and "first real value" is where churn happens.

UserTour (self-hosted on Railway) lets us trigger contextual walkthroughs based on per-user traits — no code changes per tour, just rules in the UserTour dashboard. Traits are pushed in two ways:

- **On every page load** — `UsertourProvider` (`app/providers/UsertourProvider.tsx`) calls `usertour.identify()` with live signals queried in `app/(app)/layout.tsx`.
- **Nightly batch** — `GET /api/sync-cohorts` runs at 09:00 UTC via Vercel Cron. It calls `lib/user-signals.ts` to compute behavioral signals, fetches a recommended doc from Documentation.ai for stuck users, and pushes all traits via `lib/usertour-server.ts`.

## Trait reference

| Trait | Type | Meaning |
|---|---|---|
| `plan` | string | `free` / `pro` / `pro_plus` / `enterprise` |
| `profile_complete` | bool | Has at least one business profile with name + industry |
| `vault_has_images` | bool | `vault_image_count > 0` |
| `first_idea_generated` | bool | `generated_ideas_count > 0` (dashboard-side) |
| `social_connected` | bool | Any `postforme_connections` row exists |
| `onboarding_complete` | bool | `profile_complete && first_idea_generated` |
| `stuck_score` | float | 0.0–1.0 churn risk score (nightly) |
| `last_intent` | string | `active` / `no_ideas_3d` / `low_publish_cadence` / `empty_vault` |
| `signup_days_ago` | int | Days since account creation |
| `recommended_doc_url` | string | Best-match help doc URL for stuck users |

## Tour 1 — "Your First Real Post"

**Trigger:** `first_idea_generated = false`

Users arrive with a complete profile and one idea from `/free-trial`, but that idea was generated anonymously. This tour walks them through their first in-app Content Studio generation.

| Step | Anchor | Copy guidance |
|---|---|---|
| 1 | `nav-create` | "This is where the magic happens — let's make your first post." |
| 2 | `profile-selector` | "Your business is already loaded with your voice, audience, and industry." |
| 3 | `generate-button` | "Hit Generate any time you need a post idea. Thirty seconds or less." |
| 4 | `idea-save` | "Save this to your content library. You can schedule it from here." |

Completion fires `first_idea_generated = true` and unlocks Tour 2.

## Tour 2 — "Build Your Vault"

**Trigger:** `vault_has_images = false`, fires after Tour 1 completes or on day 2+

Posts with real business photos outperform text-only. The vault is empty at onboarding — this tour gets the first upload done.

| Step | Anchor | Copy guidance |
|---|---|---|
| 1 | `nav-vault` | "Posts with real photos perform 3× better. Your vault is empty — let's fix that." |
| 2 | `vault-upload` | "Drop in a photo from your business — workspace, product, you, your team." |
| 3 | `vault-describe` | "Tell PostGlider what's in this photo. The more detail, the better your captions." |
| 4 | `vault-tags` | "PostGlider just read your photo — these tags go into every caption that uses this image." |

Completion fires `vault_has_images = true`.

## Tour 3 — "Get Your Post Live"

**Trigger:** `social_connected = false` AND `first_idea_generated = true`

The user has content but no connected channel. This tour runs once an idea is saved and the Schedule button becomes visible on the idea card.

| Step | Anchor | Copy guidance |
|---|---|---|
| 1 | `idea-schedule` | "Ready to publish? Let's connect your social account — takes about 30 seconds." |
| 2 | `nav-connect-socials` | "PostGlider uses pre-approved connections — no Meta App Review, no setup headaches." |
| 3 | `social-add-channel` | "Choose your platform and authorize PostGlider." |
| 4 | *(post-OAuth)* | "Connected. Pick a time and PostGlider will post automatically." |

Completion fires `social_connected = true`.

## Hosting

UserTour is self-hosted on **Railway** (not a VPS). The Railway service runs the UserTour instance; the Next.js app connects to it via the three env vars below.

## Environment variables

| Variable | Purpose |
|---|---|
| `NEXT_PUBLIC_USERTOUR_TOKEN` | Client SDK token (`usertour.init()`) |
| `USERTOUR_API_URL` | Self-hosted UserTour REST API base URL (Railway) |
| `USERTOUR_API_KEY` | Bearer token for server-side `POST /v1/users` calls |
| `SYNC_TRIGGER_SECRET` | Manual trigger auth for `/api/sync-cohorts` |
| `CRON_SECRET` | Vercel Cron auth (shared with other cron routes) |

All three UserTour vars are currently blank in `.env.local`. Both code paths are guarded with silent no-ops — no user-facing errors, no broken UI — but **no tours will show and no trait data accumulates** until the vars are filled in. Set them in Vercel env vars (and `.env.local` for local dev) to activate the full pipeline without any code changes.

## Tour builder guide

Step-by-step instructions for creating all three tours in the UserTour admin dashboard. Precise enough to follow by hand or drive with a browser-automation agent.

### Prerequisites

1. `NEXT_PUBLIC_USERTOUR_TOKEN`, `USERTOUR_API_URL`, and `USERTOUR_API_KEY` are set in Vercel and `.env.local`.
2. You have admin credentials for your Railway-hosted UserTour instance.
3. Log into the UserTour dashboard at your Railway URL before starting.

### Tour 1 — "Your First Real Post"

**Create the flow**

1. Click **Flows** in the left sidebar.
2. Click **New flow**.
3. Set name: `Your First Real Post`.
4. Click **Save**.

5. Open the **Trigger** tab.
6. Click **Add condition**.
7. Attribute: `first_idea_generated` · Operator: `is` · Value: `false`.

### Verify all three tours

After publishing:

- Open your PostGlider app as a test user with `first_idea_generated = false`, `vault_has_images = false`, `social_connected = false`.
- Navigate to `/generate` — Tour 1 should trigger on the `nav-create` element.
- Save an idea — `first_idea_generated` flips to `true` on the next page load, triggering Tour 2 if vault is still empty.
- Navigate to `/gallery` — Tour 2 should trigger on `vault-upload`.
- After uploading a photo, Tour 3 triggers when an idea card's schedule button is visible.

To force-reset a tour for re-testing: open the UserTour dashboard → **Users** → find your test user → **Reset flow progress**.

| File | Role |
|---|---|

| `lib/docs-recommend.ts` | Fetches recommended doc URL from Documentation.ai for stuck users |
| `app/api/sync-cohorts/route.ts` | Batch cron endpoint — computes and pushes all traits |
