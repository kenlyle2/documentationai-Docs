## The Problem

PostGlider users authenticate via the app — they have no WordPress session and cannot access `/my-account` on postglider.com directly. The same `GET /wp-json/supawp/v1/auth/session` endpoint solves this in **two directions**, distinguished only by where `return_to` points:

- **Billing self-service** — `return_to` stays on `postglider.com/my-account`.
- **Trial account claim** (`/onboarding?mode=trial`) — `return_to` bounces back to `autonomous.postglider.com`, so a newly-claimed trial user's browser round-trips through a real WordPress session and lands back in the app.

## The Flow

```
autonomous.postglider.com/billing  (or /onboarding?mode=trial after account claim)
  → user clicks "Manage Subscription" (or claims their trial account)
  → GET postglider.com/wp-json/supawp/v1/auth/session
        ?token=<supabase-access-token>
        &return_to=<https://postglider.com/my-account | https://autonomous.postglider.com/...>
  → endpoint validates the return_to host against a trusted list,
    validates the JWT, finds-or-creates the matching WP user,
    calls wp_set_auth_cookie(), redirects to return_to
  → user lands on return_to fully authenticated (on WP or back in the app)
```

From the user's perspective: one button click (or one account-claim form submit), then they're where they should be. No WordPress login screen ever appears.

## Endpoint Reference

**`GET /wp-json/supawp/v1/auth/session`** — `handle_session_redirect()` in `class.api-user.php`.

<ParamField query="token" type="string" required>
  Access token (JWT) from the user's active session.
</ParamField>

<ParamField query="return_to" type="string" required>
  URL to redirect after the WP cookie is set. Host must be in the trusted-hosts list (see below) or it silently falls back to `postglider.com`'s homepage — no error is shown.
</ParamField>

**Handler logic:**

<Steps>
  <Step title="Validate return_to against the trusted-hosts list" icon="shield-check">
    Trusted hosts = `postglider.com` (this site) + the host parsed from the `supawp_app_callback_url` option, plus anything added via the `supawp_trusted_origins` filter (nothing currently registers that filter anywhere in the workspace).

    <Callout kind="warning">
      **This is the single point of failure for both directions of this bridge.** If `supawp_app_callback_url` doesn't match the live app domain, any `return_to` targeting that domain fails this check and silently redirects to `postglider.com`'s homepage instead — not an error page, just a confusing dead end. Confirmed live 2026-07-14 (D-2026-07-14l): this option still held the retired `https://app.postglider.com/auth/callback` after the domain split, stranding every trial-signup account claim. See "Plugin Settings" below for the current value and how to check/fix it.
    </Callout>
  </Step>
  <Step title="Validate the JWT" icon="shield">
    Decodes the token locally (peeks the header to determine `alg`, verifies via cached JWKS for RS256) — no remote call to the auth service per request.
  </Step>
  <Step title="Find or create the WP user" icon="user">
    Extracts `sub` (Supabase UID) and `email` from the decoded JWT. Calls `get_or_create_user($supabase_uid, $email, null)` — if no matching WP account exists yet, one is created here, not just looked up.
  </Step>
  <Step title="Set the WP auth cookie and redirect" icon="cookie">
    Calls `wp_set_current_user()` + `wp_set_auth_cookie($user->ID, true, is_ssl())`, sets a short-lived transient (`supawp_cross_domain_{user_id}`, default 8h) so the WP-side Supabase client's own `SIGNED_OUT` state doesn't immediately undo the cookie, then `wp_redirect(esc_url_raw($return_to))`.
  </Step>
</Steps>

## supawp-pg Plugin

**Repo:** `kenlyle2/supawp-pg` — fork of techcater's open-source SupaWP, modified for PostGlider. The techcater license updater is replaced with a GitHub-release auto-updater (same pattern as `pg-media-vault`).

**Local path:** `~/projects/supawp`
**Version scheme:** semantic version + lowercase letter suffix from `b` onward. Current: `1.12.0t`

### Additional Capabilities

| Endpoint / Feature | Purpose |
|---|---|
| `GET /wp-json/supawp/v1/auth/session` | Session bridge (described above) |
| `POST /wp-json/supawp/v1/auth/auto-login` | JS background auto-login on WP page load |
| `?supawp_launch_app=1` query param | Reverse direction: logged-in WP user → magic link → app |

### Plugin Settings (`supawp_options`)

| Key | Purpose |
|---|---|
| `supawp_supabase_url` | PostGlider auth service URL |
| `supawp_service_role_key` | Used by `launch_app` to generate magic links |
| `supawp_jwt_secret` | HS256 JWT validation (not required — plugin uses ES256/JWKS automatically) |
| `supawp_app_callback_url` | **Must match the live app domain** — currently `https://autonomous.postglider.com/auth/callback`. Only its host is used (trusted-hosts check above); the launch-app redirect target also reads this value verbatim, so keep the full path correct too. Check the live value: `wp option get supawp_options --format=json --path=<wp-root>` |

### Deploying a New Version

```bash
cd ~/projects/supawp
# make changes, bump version in init.php + metadata.json
git add -A && git commit -m "feat(plugin): vX.Y.Za — description"
git push
git tag v1.12.0x && git push origin v1.12.0x
```

GitHub Actions builds `supawp.zip`. Download from the release and install via **WP Admin → Plugins → Add New → Upload** on postglider.com (standard zip upload works here). Auto-updater polls `metadata.json` every 12 hours thereafter.

## Prerequisites

- `supawp-pg` must be installed and network-activated on **postglider.com** (the marketing/billing site)
- The `postglider_anon_key` site option must be populated (set via `configure-site` API or wp-admin)
- WordPress/WooCommerce customer accounts are created automatically when a PostGlider account is claimed (via `POST /api/auth/claim`), not at checkout. WooCommerce self-registration is disabled. See [Auth & Credits → WooCommerce Customer Mirror](/admin/auth-and-credits#woocommerce-customer-mirror).
