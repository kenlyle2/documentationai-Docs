## XState in the Generate Page

The `/generate` page is driven by a formal XState v5 state machine at `@/lib/machines/postgliderMachine.ts`. All logical switches — loading states, modal visibility, active stage — are driven by `state.matches('state_name')`, not local booleans.

State flow: `initializing → idle → generating_text → tinder_review → viewing_idea → planning_image → generating_image → selecting_variant → error`

Realtime listeners for image updates trigger XState events (`VARIANTS_ARRIVED`) rather than setting local booleans.

## Week Pack Generator — Technical Notes

The Week Pack Generator is a pure client-side planning step that runs before any generation API call is made. No new backend or DB schema is involved.

| File | Role |
|---|---|
| `lib/utils/weekPackPlanner.ts` | Pure function: `buildWeekPlan(bubbles, photos, recentIdeas, weekBatchSize) → WeekPlanSlot[]` |
| `lib/utils/imageCoherence.ts` | Scores vault images against bubble labels via keyword overlap + category expansion map. No API call. |
| `components/generate/WeekPackReview.tsx` | Modal UI: 7-slot review with editable directions, photo thumbnails, category badges |
| `app/(app)/generate/page.tsx` | Intercepts the `handleGenerate` callback in Pilot Mode; shows `WeekPackReview` before sending `GENERATE` to the XState machine |

**Distribution algorithm:** 1 promote slot is hard-reserved (Thursday, index 3). The remaining 6 slots are distributed proportionally across the user's selected Genie bubbles, weighted by each category's deficit against the 20/40/40 content balance target. An interleaving pass ensures the week isn't front-loaded with one theme.

**Photo assignment:** The planner scores each vault photo against each slot's bubble label using `scoreImageForBubble()`, then assigns greedily (highest coherence score first, each photo used at most once).

**Virality Engine stub:** Each `WeekPlanSlot` has a `viralityHint?: string` field. When the Virality Engine is integrated, it populates this field; the UI already renders it as a green "Virality boost" badge. No further schema or component changes needed at that point.

**Social publishing (PostforMe):** PostGlider operates one shared PostforMe Team account. The `POSTFORME_API_KEY` environment variable (server-side only, never exposed to the browser) authenticates all calls via the `post-for-me` SDK (v2.7+). Two Route Handlers proxy PostforMe on behalf of authenticated users: `GET /api/postforme/connect?platform=<platform>` (returns an OAuth URL) and `GET /api/postforme/integrations` (returns the current integration list). Connected channels are stored in `postforme_connections` (Supabase, RLS-scoped to business profile owner).

## Pilot Mode Drip Gate

`pilot_eligible` on the `profiles` table is set to `true` by a daily pg_cron job (`pilot-mode-drip`, runs midnight UTC). Threshold is configurable in `admin_settings` under `feature_drip.pilot_mode_days` (default: 7 days).

The column has `REVOKE UPDATE` from the `authenticated` role — users cannot self-elevate via the browser SDK. A backfill migration runs on deployment to immediately grant eligibility to accounts that already qualify.
